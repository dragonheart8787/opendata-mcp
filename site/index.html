帶著查到的 datasetId 執行實際查詢——只接受已登記的 id，不接受任意網址，避免被當跳板打任意上游 API。

GET STARTED

怎麼開始使用

路線 01

用公開 demo 服務

打開 claude.ai → 左下角設定 → Connectors → Add custom connector → 貼上下方網址，存檔後直接問「臺北市明天天氣如何？」。

https://opendata-mcp.dragonheartliu1440.workers.dev/mcp

這是一個公開展示（demo）服務，僅供測試使用，沒有登入機制、沒有專屬額度保證。流量較大時可能回應較慢，也可能因為共用的官方 API 額度用完而暫時查不到資料。

同樣的網址也可以接進 ChatGPT、Cursor、Windsurf、Cline 等任何 MCP 相容平台，不需要任何驗證設定。

路線 02

自行部署一份

完全免費，約 10–15 分鐘，不需要自己的伺服器。長期穩定使用（尤其是 TDX 那四個工具）建議走這條。

  1. Fork 這個 repo 到你的 GitHub
  2. Cloudflare Dashboard → Workers & Pages → Create → Import an existing Git repository，選你 Fork 的 repo 直接部署
  3. Settings → Variables and Secrets，加上 CWA_API_KEY、MOENV_API_KEY、TDX_CLIENT_ID、TDX_CLIENT_SECRET（用 Secret，不要用一般環境變數）
  4. 建立自己的快取 KV namespace，把 wrangler.toml 裡的 id 換掉
  5. 之後 push 到 main 就會自動重新部署

金鑰都是免費申請；國道事件完全公開、不需要金鑰。沒設定金鑰的工具會回傳明確錯誤訊息，不會讓整個服務掛掉。完整步驟見 README 的「自行部署」章節。

QUALITY GATES

品質保證

三個 GitHub Actions workflow 做持續性把關，設計成不依賴人工手動驗證，讓貢獻者可以放心送 PR。三者都能在 Actions 分頁手動觸發。

ci.yml TRIGGER · 每個 PR
01typecheck
02跑全部單元測試（目前 333 個）
03wrangler deploy --dry-run 確認建置成功

任一步驟失敗，PR 會顯示紅叉、不可合併。

fixtures-refresh.yml TRIGGER · 每週一次
01對每個已註冊資料集打一次真實 API
02與 fixtures 做結構性比對（欄位、型別，不比對數值）
03上游改格式 → 自動開 schema-drift PR 與 issue

在猜錯格式的問題影響到使用者之前，先在自動化流程裡抓到。

post-deploy-smoke-test.yml TRIGGER · push 到 main 後
01initialize 真實 MCP 請求
02tools/list 確認所有工具正確曝光
03依序真實呼叫幾個工具，確認回應信封格式正確

失敗會自動開一個標記 smoke-test-failed 的 issue。
